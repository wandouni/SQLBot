## 通用判定规则

- **口径优先于数值**：口径错误即使数字接近也判失败；口径正确而数值仅因四舍五入有微小差异可判通过。
- 数值容差：人数、金额精确；百分比 ±0.01 个百分点；比例 ±0.1 个百分点；加权平均起薪 ±1 元。
- 百分比字段（如 `就业率(%)`）是百分数数值，`95.52` 表示 95.52%，不是 0.9552。
- 金额字段以列名为准：`(万元)` 为万元，`生均教育经费(元)`、`平均起薪(元/月)`、`学费标准(元/年)` 为元。
- 术语是否命中，以聊天日志中 `FILTER_TERMS` 环节的记录为准。
- 图表题只校验数据系列与数值，不强制指定图表类型；但趋势题应优先折线图、分类对比题应优先柱状图或表格。

## 数据口径说明

以下为数据集的设计口径，**不属于缺陷，也不应作为模型能力判定依据**（此前的“及格率全部相同”“在校生规模不一致”两项生成缺陷已修复，相关用例见 D-06、B-02）：

1. `办学条件` 的教学仪器设备总值（22,800 万元）与 `教学资源` 各院系设备值合计（12,137 万元）本身是“全校口径 vs 院系口径”，差异属预期设计，不是错误（见 B-03）。
2. `校企合作` 表没有“年份”字段，只有“签订日期”；涉及年份的问题必须明确按签订日期过滤（见 B-04）。
3. 招生录取按“省份 × 专业 × 批次”拆行，汇总人数时必须求和，不能去重（见 B-02、C-01）。
4. `就业率(%)` 为“毕业去向落实率”，分母是毕业生数，不含升学人数的口径差异；跨表计算院系就业率时必须重新汇总人数，不能对专业就业率取简单平均（见 C-04）。

## 配置变更与复测（2026-10-28）

首次执行暴露的问题主要来自两个可配置项：缺少同类问题的 SQL 示例，以及部分术语描述未写明口径。根据失败原因做了以下配置层变更，未改动业务代码：

| 变更 | 内容 |
| --- | --- |
| 术语描述 | `生均教育经费`（id 33）改为直接取 `财务收支` 表的 `生均教育经费(元)` 字段，不再用支出合计推算；`平均起薪`（id 12）补充“跨专业/院系/全校汇总必须按毕业生数加权” |
| 新增术语 | `课程教学`（id 73，同义词 `课程成绩`、`课程`），要求课程成绩/及格率查询同时输出学年、学期、院系名称 |
| SQL 示例 | 新增 4 条：财政拨款占比（含 `::numeric` 转型）、加权平均起薪、生均教育经费、最低平均成绩课程；见 `SQL示例导入.xlsx` |
| 数据源勾选 | 取消勾选 `数据说明`，业务表 10/10 参与问答（`num=10/11`） |

复测范围：8 条原失败/部分通过用例（A-02、A-04、C-01、D-03、D-04、D-05、D-06、E-01）加 6 条回归用例（A-01、A-03、A-05、C-02、C-05、D-01）。结果全部符合预期，无回归。其中 A-04 第一次复测仍报 `round(double precision, integer)`，原因是新增的 SQL 示例 1 漏了整体 `::numeric` 转型；修正示例后重测得到 57.78%。

随后补跑初测通过但未复验的 10 条（A-06、B-01～B-05、C-03、C-04、D-02、E-02），结果与初测一致，至此 A～E 组 24 条全部在配置变更后复验通过。

配置变更后汇总：通过 26 条、部分通过 1 条、不通过 0 条、反例未观察到差异 0 条。
